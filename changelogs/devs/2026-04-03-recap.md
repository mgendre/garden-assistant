### Backend — E21 Upsert des seeders

- **Entity `Plant`** : ajout de `Key` (string, cle metier stable pour le mapping seed/BDD), `IsCustomized` (bool, protection contre l'ecrasement par les seeds), `UserId` (Guid?, preparation aux variantes utilisateur). Index unique sur `Key` filtre `WHERE UserId IS NULL`
- **5 seeders convertis en upsert** : `PlantSeeder`, `AssociationSeeder`, `PlantActionSeeder`, `HarvestReadinessSeeder`, `GuildSeeder`. Chaque seeder identifie les entites par `Key` ou `Name`, met a jour les champs modifies, et protege les entites `IsCustomized = true`
- **Refactoring structurel** : extraction des record types (`PlantSeedRecord`, `AssociationSeedRecord`, etc.) dans `Data/Seeders/Records/`, extraction des `JsonConverter` dans `Data/Seeders/Converters/`, decomposition en methodes nommees (`UpsertPlant`, `SyncMechanisms`, etc.)
- **152+ tests** : `PlantSeederTests` (44+), `AssociationSeederTests`, adaptation des fixtures existantes pour inclure `Key`, `IsCustomized`, `UserId`
- **Performance** : `Stopwatch` sur chaque seeder avec logs de timing

### Backend — E24 Sol et pH

- **Enum `SoilType`** : 7 valeurs — `Sandy`, `Silty`, `Clay`, `Loam`, `Chalky`, `Peaty`, `Rocky`
- **Entity `PlantSoilType`** : table de jointure many-to-many `Plant` <-> `SoilType`, configuree en Fluent API
- **Entity `Plant`** : ajout de `OptimalPhMin` (decimal?) et `OptimalPhMax` (decimal?)
- **Migration EF Core** : table `plant_soil_types`, colonnes `optimal_ph_min` / `optimal_ph_max` sur `plants`
- **Seed data** : 159 plantes enrichies avec types de sols et plages de pH, validees par `plant-expert`
- **PlantDto** : inclut desormais `SoilTypes` (List<string>), `OptimalPhMin`, `OptimalPhMax`, `HarvestReadiness` et `Actions` en un seul appel API
- **Endpoints supprimes** : les endpoints separes pour `harvest-readiness` et `actions` sont supprimes, ces donnees etant integrees dans `PlantDto`
- **Performance** : `AsSplitQuery()` sur les requetes multi-Include dans `PlantService` et `UserPlantService`

### Frontend — Redesign du catalogue

- **Layout sidebar/liste** : le template `plant-catalogue.html` passe d'une liste de filtres horizontaux a un layout `catalogue-body` en deux colonnes (40% filtres / 60% liste sur desktop, empile sur mobile)
- **Filtres en sections repliables** : 4 groupes utilisant `<app-collapsible>` — mecanismes, profondeur racinaire, type de sol, pH. Chaque filtre est un `<button class="filter-item">` avec etat `--active`
- **Indicateur de filtre actif** : `.filter-active-dot` (point vert) sur les en-tetes de section quand un filtre est selectionne
- **Bouton de reinitialisation** : `resetFilters()` remet tous les filtres a leur etat par defaut, visible uniquement quand `hasActiveFilters()` est vrai
- **Tri en barre compacte** : `.sort-bar` avec `.sort-btn` remplace les anciens `.chip` dans `.sort-wrap`
- **Liste de plantes epuree** : badges de mecanismes retires de la liste, famille affichee sous le nom (`flex-col`), icones reduites (28px), coeur inline avec le nom de la plante
- **Traductions** : ajout de `Companions.ResetFilters`, `Companions.Filters`, `Companions.SortLabel`, `Companions.FilterMechanisms`, `Companions.FilterRootDepth`, `Companions.FilterSoilPh`, `Companions.FilterSoilType`, `Companions.FilterPh`

### Frontend — Sol et pH

- **Fiche plante** : section "Sol & pH" avec chips de sol (`.soil-chip`) et barre de pH a gradient (`.ph-scale` + `.ph-range`)
- **Guild assistant** : `phConflictPairs` computed signal dans `CompanionStore`, avertissement visuel des paires de plantes incompatibles en pH
- **Filtres catalogue** : filtre pH compatible (actif par defaut), filtre par type de sol

### Frontend — Divers

- **Layout** : `page-container` elargi a `max-w-[1500px]`, ajout d'une classe `.three-col` dans `_layout.scss` pour les layouts a trois colonnes
- **Nettoyage** : suppression de `catalog-2.png` (screenshot de dev)

### Tests

### Points d'attention

- **Migration requise** : table `plant_soil_types` + colonnes `optimal_ph_min`/`optimal_ph_max` sur `plants` + colonne `key` avec index unique filtre
- Les endpoints separes `harvest-readiness` et `actions` sont supprimes — les clients doivent utiliser les champs inclus dans `PlantDto`
- Le champ `UserId` sur `Plant` prepare l'epic de variantes utilisateur mais n'est pas encore exploite par l'API
- Le filtre pH compatible est actif par defaut dans le catalogue — comportement voulu pour guider les utilisateurs
