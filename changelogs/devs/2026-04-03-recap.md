### Backend — E21 Upsert des seeders

- **Entity `Plant`** : ajout de `Key` (string, clé métier stable pour le mapping seed/BDD), `IsCustomized` (bool, protection contre l'écrasement par les seeds), `UserId` (Guid?, préparation aux variantes utilisateur). Index unique sur `Key` filtré `WHERE UserId IS NULL`
- **5 seeders convertis en upsert** : `PlantSeeder`, `AssociationSeeder`, `PlantActionSeeder`, `HarvestReadinessSeeder`, `GuildSeeder`. Chaque seeder identifie les entités par `Key` ou `Name`, met à jour les champs modifiés, et protège les entités `IsCustomized = true`
- **Refactoring structurel** : extraction des record types (`PlantSeedRecord`, `AssociationSeedRecord`, etc.) dans `Data/Seeders/Records/`, extraction des `JsonConverter` dans `Data/Seeders/Converters/`, décomposition en méthodes nommées (`UpsertPlant`, `SyncMechanisms`, etc.)
- **152+ tests** : `PlantSeederTests` (44+), `AssociationSeederTests`, adaptation des fixtures existantes pour inclure `Key`, `IsCustomized`, `UserId`
- **Performance** : `Stopwatch` sur chaque seeder avec logs de timing

### Backend — E24 Sol et pH

- **Enum `SoilType`** : 7 valeurs — `Sandy`, `Silty`, `Clay`, `Loam`, `Chalky`, `Peaty`, `Rocky`
- **Entity `PlantSoilType`** : table de jointure many-to-many `Plant` <-> `SoilType`, configurée en Fluent API
- **Entity `Plant`** : ajout de `OptimalPhMin` (decimal?) et `OptimalPhMax` (decimal?)
- **Migration EF Core** : table `plant_soil_types`, colonnes `optimal_ph_min` / `optimal_ph_max` sur `plants`
- **Seed data** : 159 plantes enrichies avec types de sols et plages de pH, validées par `plant-expert`
- **PlantDto** : inclut désormais `SoilTypes` (List<string>), `OptimalPhMin`, `OptimalPhMax`, `HarvestReadiness` et `Actions` en un seul appel API
- **Endpoints supprimés** : les endpoints séparés pour `harvest-readiness` et `actions` sont supprimés, ces données étant intégrées dans `PlantDto`
- **Performance** : `AsSplitQuery()` sur les requêtes multi-Include dans `PlantService` et `UserPlantService`

### Frontend — Redesign du catalogue

- **Layout sidebar/liste** : le template `plant-catalogue.html` passe d'une liste de filtres horizontaux à un layout `catalogue-body` en deux colonnes (40% filtres / 60% liste sur desktop, empilé sur mobile)
- **Filtres en sections repliables** : 4 groupes utilisant `<app-collapsible>` — mécanismes, profondeur racinaire, type de sol, pH. Chaque filtre est un `<button class="filter-item">` avec état `--active`
- **Indicateur de filtre actif** : `.filter-active-dot` (point vert) sur les en-têtes de section quand un filtre est sélectionné
- **Bouton de réinitialisation** : `resetFilters()` remet tous les filtres à leur état par défaut, visible uniquement quand `hasActiveFilters()` est vrai
- **Tri en barre compacte** : `.sort-bar` avec `.sort-btn` remplace les anciens `.chip` dans `.sort-wrap`
- **Liste de plantes épurée** : badges de mécanismes retirés de la liste, famille affichée sous le nom (`flex-col`), icônes réduites (28px), cœur inline avec le nom de la plante
- **Traductions** : ajout de `Companions.ResetFilters`, `Companions.Filters`, `Companions.SortLabel`, `Companions.FilterMechanisms`, `Companions.FilterRootDepth`, `Companions.FilterSoilPh`, `Companions.FilterSoilType`, `Companions.FilterPh`

### Frontend — Sol et pH

- **Fiche plante** : section « Sol & pH » avec chips de sol (`.soil-chip`) et barre de pH à gradient (`.ph-scale` + `.ph-range`)
- **Guild assistant** : `phConflictPairs` computed signal dans `CompanionStore`, avertissement visuel des paires de plantes incompatibles en pH
- **Filtres catalogue** : filtre pH compatible (actif par défaut), filtre par type de sol

### Frontend — Divers

- **Layout** : `page-container` élargi à `max-w-[1500px]`, ajout d'une classe `.three-col` dans `_layout.scss` pour les layouts à trois colonnes
- **Nettoyage** : suppression de `catalog-2.png` (screenshot de dev)

### Tests

### Points d'attention

- **Migration requise** : table `plant_soil_types` + colonnes `optimal_ph_min`/`optimal_ph_max` sur `plants` + colonne `key` avec index unique filtré
- Les endpoints séparés `harvest-readiness` et `actions` sont supprimés — les clients doivent utiliser les champs inclus dans `PlantDto`
- Le champ `UserId` sur `Plant` prépare l'epic de variantes utilisateur mais n'est pas encore exploité par l'API
- Le filtre pH compatible est actif par défaut dans le catalogue — comportement voulu pour guider les utilisateurs
