### Backend

- **Entity** : ajout de `ParentPlantId` (Guid?, self-referencing FK) sur l'entite `Plant` avec migration EF Core. Relation `Parent` / `Varieties` configuree en Fluent API (US-306)
- **PlantSeeder** : seeding en deux passes — les especes parentes d'abord, puis les varietes via le champ `parentKey` dans les fichiers JSON (US-307)
- **Seed data** : 27+ varietes ajoutees sur 17 especes parentes (tomate, courge, haricot, basilic, pois, laitue, fraisier, framboisier, poivron, piment, chou, radis, fenouil, concombre, tournesol). Restructuration complete du haricot : fusion haricot-nain/haricot-a-rames en un parent unique avec 10 varietes. Ajout du haricot d'Espagne (P. coccineus) et de la courge musquee comme nouvelles especes (US-308, US-308a, US-308b)
- **Calendriers variete** : actions specifiques par variete (tomate-naine sans taille, framboisier-d-automne, radis-d-hiver, courge-musquee, haricot-a-ecosser). Heritage des actions du parent quand la variete n'en definit pas (US-308)
- **PlantService** : heritage des proprietes (`WaterNeeds`, `SunRequirement`, `SoilType`, `RootDepth`, `GrowthHabit`, `Lifecycle`, famille, genre) et des mecanismes (`PlantMechanisms`) du parent vers la variete. Heritage de `HarvestReadiness` et des actions calendrier (US-309)
- **PlantAssociationService** : resolution transparente des varietes vers leur parent pour le scoring d'associations. Les DTOs retournent les IDs de varietes d'origine mais affichent l'espece parente dans les details (US-310)
- **Validation seed data** : tests xUnit verifiant les enums (`SunRequirement`, `SoilType`, etc.) dans tous les fichiers JSON de seed. Correction de valeurs invalides detectees (US-308)

### Frontend

- **NSwag** : client TypeScript regenere avec les champs `parentPlantId`, `parentPlantKey`, `isVariety` sur `PlantDto` (US-311)
- **Plant cards** : application du style `.panel` (border + shadow) aux cartes de plantes dans la page "Mes plantes"
- **Plant detail dialog** : correction du double padding et du padding-top excessif
- **Association panels** : suppression de la bordure/ombre sur les plant-cards a l'interieur des panels d'association et de detail pour eviter la double bordure

### Infrastructure

- Aucun changement d'infrastructure dans cette branche

### Points d'attention

- L'heritage de proprietes se fait au niveau service (pas en BDD) : une variete sans valeur propre recoit celle de son parent au runtime
- Les associations d'une variete sont resolues via le `ParentPlantId` — aucune association n'est stockee directement sur les varietes
- Le seeding deux passes impose que les fichiers JSON de varietes referent un `parentKey` correspondant au `Key` d'une espece existante
- Les tests de validation des seed data (`SeedDataValidationTests`) sont a maintenir lors de l'ajout de nouvelles plantes ou varietes
- Le backlog E20 n'est pas encore marque comme termine — a mettre a jour apres merge
