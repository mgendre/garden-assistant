### Backend

- **Enum `SoilType`** : ajout de 7 valeurs — `Sandy`, `Silty`, `Clay`, `Loam`, `Chalky`, `Peaty`, `Rocky`
- **Entity `PlantSoilType`** : nouvelle table de jointure many-to-many entre `Plant` et `SoilType`, configurée en Fluent API dans `AppDbContext`
- **Entity `Plant`** : ajout de `OptimalPhMin` (decimal?) et `OptimalPhMax` (decimal?) pour la plage de pH optimale
- **Migration EF Core** : creation de la table `plant_soil_types` et des colonnes `optimal_ph_min` / `optimal_ph_max` sur `plants`
- **PlantSeeder** : upsert des `SoilTypes` et des champs pH depuis `plants.json`. Le `PlantSeedRecord` est enrichi avec les champs `soilTypes` (liste de strings) et `optimalPhMin` / `optimalPhMax` (décimales)
- **Seed data** : les 159 plantes de `plants.json` sont enrichies avec leurs types de sols et plages de pH, donnees validees par l'agent `plant-expert`
- **PlantService** : `Include(p => p.SoilTypes)` et `ThenInclude` sur le parent pour l'héritage variété. Le mapping DTO expose `SoilTypes` (liste de strings), `OptimalPhMin` et `OptimalPhMax` avec héritage parent → variété
- **PlantDto** : ajout des champs `SoilTypes` (List<string>), `OptimalPhMin` (decimal?) et `OptimalPhMax` (decimal?)
- **UserPlantService** : inclusion des `SoilTypes` dans les requetes utilisateur

### Frontend

- **Client API** : regeneration NSwag avec les champs `soilTypes`, `optimalPhMin`, `optimalPhMax` sur `PlantDto`
- **Plant card** : affichage des types de sol en chips (`.soil-chip`) dans une `info-card-wide`. Affichage de la plage de pH via une barre visuelle à gradient (`.ph-scale` + `.ph-range`) avec labels acide/neutre/alcalin et valeur numérique. Méthodes `getPhLeftPercent()` et `getPhWidthPercent()` pour le positionnement CSS du range indicator
- **Info card SCSS** : ajout de `.info-card-wide`, `.info-card-chips`, `.soil-chip`, `.ph-display`, `.ph-scale`, `.ph-range`, `.ph-labels`, `.ph-value` dans `_info-card.scss`
- **Guild assistant** : affichage des conflits de pH via le signal `phConflictPairs` du `CompanionStore`. Avertissement visuel listant les paires de plantes incompatibles avec leurs plages de pH respectives
- **CompanionStore** : nouveau `computed` signal `phConflictPairs` — détection de non-chevauchement des plages `[optimalPhMin, optimalPhMax]` entre toutes les paires de plantes sélectionnées
- **Traductions** : ajout des cles `Plant.Soil.Label`, `Plant.Soil.Sandy/Silty/Clay/Loam/Chalky/Peaty/Rocky`, `Plant.Ph.Label`, `Plant.Ph.Acid`, `Plant.Ph.Neutral`, `Plant.Ph.Alkaline`, `Plant.Ph.Aria` dans `fr.json`

### Tests

- **PlantSeederTests** : 3 nouveaux tests couvrant l'upsert des soil types et des champs pH (insertion, mise à jour, idempotence)
- **PlantServiceTests** : 4 nouveaux tests couvrant le mapping DTO des soil types et du pH, ainsi que l'heritage variete -> parent pour ces champs
- **CalendarControllerTests** : adaptation des fixtures pour inclure les nouveaux champs `OptimalPhMin`, `OptimalPhMax` et `SoilTypes` sur les instances de `Plant`

### Points d'attention

- La migration EF Core ajoute la table `plant_soil_types` et deux colonnes nullable sur `plants` — à appliquer avant déploiement
- L'héritage sol/pH pour les variétés suit la même logique que les autres propriétés : la variété prime si elle a des valeurs propres, sinon le parent est utilisé
- Le signal `phConflictPairs` dans `CompanionStore` détecte la non-intersection stricte des plages pH — deux plantes sont considérées incompatibles uniquement si leurs plages ne se chevauchent pas du tout
- Le backlog E24 est désormais terminé
