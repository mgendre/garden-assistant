### Backend

- **Entity `Plant`** : ajout de trois champs — `Key` (string, clé métier stable pour le mapping seed/BDD), `IsCustomized` (bool, flag de protection contre l'écrasement par les seeds), `UserId` (Guid?, préparation au support des variantes utilisateur). Configuration Fluent API dans `AppDbContext` avec index unique sur `Key` filtré `WHERE UserId IS NULL`
- **PlantSeeder** : refonte complète du mode « insert if empty » vers un mode upsert en deux passes (espèces puis variétés). Chaque plante est identifiée par `Key`. Les plantes existantes non personnalisées sont mises à jour (propriétés + mécanismes intrinsèques) avec log des champs modifiés. Les plantes `IsCustomized = true` sont ignorées avec un log `Debug`. Injection de `ILogger<PlantSeeder>`
- **AssociationSeeder** : conversion en upsert par lookup direct via `Key` (au lieu de l'ancien key → name → DB). Insertion des nouvelles associations, mise à jour du `Relationship` si modifié, skip des associations impliquant des plantes personnalisées
- **PlantActionSeeder** : conversion en upsert. Les actions existantes sont mises à jour (mois, description), les nouvelles insérées. Les plantes personnalisées sont protégées
- **HarvestReadinessSeeder** : conversion en upsert. Le `HarvestReadiness` existant est mis à jour champ par champ, les nouveaux sont insérés. Protection des plantes personnalisées
- **GuildSeeder** : conversion en upsert. Les guildes existantes sont identifiées par `Name`, leurs membres mis à jour (ajout/suppression). Les guildes référençant des plantes personnalisées sont ignorées
- **Refactoring structurel** : extraction des record types (`PlantSeedRecord`, `AssociationSeedRecord`, etc.) dans des fichiers séparés sous `Data/Seeders/Records/`. Extraction des `JsonConverter` dans `Data/Seeders/Converters/`. Décomposition des méthodes longues en méthodes privées nommées (`LoadSeedRecords`, `LoadExistingPlantsWithMechanisms`, `UpsertPlant`, `UpdatePlantProperties`, `SyncMechanisms`, etc.)

### Frontend

- **Calendrier** : remplacement des boutons de filtre source et groupement par le composant `<app-toggle-group>`. Suppression de l'import `FontAwesomeModule` au profit d'imports directs d'icônes. Les options de source (`all`, `myPlants`, `gardenPlants`) et de groupement (`flat`, `byGarden`) sont déclarées comme `ToggleOption[]` dans le composant
- **Garden calendar** : même refactoring toggle-group appliqué au calendrier par jardin
- **Design system** : ajout de la classe `.btn-group` dans `_buttons.scss` (inline-flex, bordure partagée, border-radius aux extrémités) pour le composant toggle-group

### Tests

- **PlantSeederTests** : 44+ tests couvrant les chemins insert, update, skip customized, idempotence, mécanismes intrinsèques (ajout/suppression/update), variétés, erreurs de parentKey manquant
- **AssociationSeederTests** : tests d'upsert (insert, update relationship, skip customized, idempotence)
- **SeedDataValidationTests** : simplification — suppression des validations devenues redondantes avec le typage par records
- **Tests existants** : adaptation des fixtures pour inclure les nouveaux champs `Key`, `IsCustomized`, `UserId` sur les instances de `Plant`

### Points d'attention

- La colonne `Key` est obligatoire sur `Plant` — une migration EF Core est nécessaire (`Key` string required + index unique filtré)
- Le flag `IsCustomized` est à `false` par défaut — seule une action explicite de l'administrateur ou de l'utilisateur le passe à `true`
- Les seeders loggent les modifications en `Information` et les skips en `Debug` — utile pour le diagnostic en production
- Le champ `UserId` sur `Plant` prépare l'epic de variantes utilisateur mais n'est pas encore exploité par les endpoints API
