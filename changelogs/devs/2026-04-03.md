### Backend

- **Entity `Plant`** : ajout de trois champs — `Key` (string, cle metier stable pour le mapping seed/BDD), `IsCustomized` (bool, flag de protection contre l'ecrasement par les seeds), `UserId` (Guid?, preparation au support des variantes utilisateur). Configuration Fluent API dans `AppDbContext` avec index unique sur `Key` filtre `WHERE UserId IS NULL`
- **PlantSeeder** : refonte complete du mode "insert if empty" vers un mode upsert en deux passes (especes puis varietes). Chaque plante est identifiee par `Key`. Les plantes existantes non personnalisees sont mises a jour (proprietes + mecanismes intrinseques) avec log des champs modifies. Les plantes `IsCustomized = true` sont ignorees avec un log `Debug`. Injection de `ILogger<PlantSeeder>`
- **AssociationSeeder** : conversion en upsert par lookup direct via `Key` (au lieu de l'ancien key -> name -> DB). Insertion des nouvelles associations, mise a jour du `Relationship` si modifie, skip des associations impliquant des plantes personnalisees
- **PlantActionSeeder** : conversion en upsert. Les actions existantes sont mises a jour (mois, description), les nouvelles inserees. Les plantes personnalisees sont protegees
- **HarvestReadinessSeeder** : conversion en upsert. Le `HarvestReadiness` existant est mis a jour champ par champ, les nouveaux sont inseres. Protection des plantes personnalisees
- **GuildSeeder** : conversion en upsert. Les guildes existantes sont identifiees par `Name`, leurs membres mis a jour (ajout/suppression). Les guildes referençant des plantes personnalisees sont ignorees
- **Refactoring structurel** : extraction des record types (`PlantSeedRecord`, `AssociationSeedRecord`, etc.) dans des fichiers separes sous `Data/Seeders/Records/`. Extraction des `JsonConverter` dans `Data/Seeders/Converters/`. Decomposition des methodes longues en methodes privees nommees (`LoadSeedRecords`, `LoadExistingPlantsWithMechanisms`, `UpsertPlant`, `UpdatePlantProperties`, `SyncMechanisms`, etc.)

### Frontend

- **Calendrier** : remplacement des boutons de filtre source et groupement par le composant `<app-toggle-group>`. Suppression de l'import `FontAwesomeModule` au profit d'imports directs d'icones. Les options de source (`all`, `myPlants`, `gardenPlants`) et de groupement (`flat`, `byGarden`) sont declarees comme `ToggleOption[]` dans le composant
- **Garden calendar** : meme refactoring toggle-group applique au calendrier par jardin
- **Design system** : ajout de la classe `.btn-group` dans `_buttons.scss` (inline-flex, bordure partagee, border-radius aux extremites) pour le composant toggle-group

### Tests

- **PlantSeederTests** : 44+ tests couvrant les chemins insert, update, skip customized, idempotence, mecanismes intrinseques (ajout/suppression/update), varietes, erreurs de parentKey manquant
- **AssociationSeederTests** : tests d'upsert (insert, update relationship, skip customized, idempotence)
- **SeedDataValidationTests** : simplification — suppression des validations devenues redondantes avec le typage par records
- **Tests existants** : adaptation des fixtures pour inclure les nouveaux champs `Key`, `IsCustomized`, `UserId` sur les instances de `Plant`

### Points d'attention

- La colonne `Key` est obligatoire sur `Plant` — une migration EF Core est necessaire (`Key` string required + index unique filtre)
- Le flag `IsCustomized` est a `false` par defaut — seule une action explicite de l'administrateur ou de l'utilisateur le passe a `true`
- Les seeders loggent les modifications en `Information` et les skips en `Debug` — utile pour le diagnostic en production
- Le champ `UserId` sur `Plant` prepare l'epic de variantes utilisateur mais n'est pas encore exploite par les endpoints API
