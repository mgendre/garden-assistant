### Backend

- Entités `Garden` et `Bed` avec champs `Name`, `UserId`, relations one-to-many
- DTOs : `GardenDto`, `CreateGardenRequest`, `UpdateGardenRequest`, `BedDto`, `CreateBedRequest`, `UpdateBedRequest`
- `IGardenService` / `GardenService` : CRUD jardins avec filtrage par `UserId`
- `IBedService` / `BedService` : CRUD planches rattachées à un jardin
- `GardensController` (`api/gardens`) et `BedsController` (`api/gardens/{gardenId}/beds`) avec routes RESTful en kebab-case
- Migration EF Core pour les tables `gardens` et `beds` (snake_case)

### Frontend

- **GardenService** et **GardenStore** : gestion d'état par signaux Angular, chargement des jardins et planches avec plantes associées
- **GardenListComponent** : liste des jardins en panel avec items divisés, tri alphabétique
- **GardenViewComponent** : vue détail d'un jardin avec planches en collapsibles, boutons modifier/supprimer côte à côte, breadcrumb de retour
- **Bed panels** : affichage des plantes en lecture seule via `PlantAssociationPanel`, section d'actions avec bouton « Modifier », calendrier par planche
- **PlantBadge** (`PlantBadgeComponent`) : nouveau composant réutilisable affichant le nom d'une plante en badge coloré. Utilisé dans les en-têtes de planches, les cartes de guildes et l'assistant de guildes. Supporte les inputs `plantId` + `plantName`, clic pour ouvrir le détail
- **Calendrier global jardin** : intégration des plantes de jardins dans le calendrier principal avec filtre source (toutes / mes plantes / jardins) et regroupement par jardin avec en-têtes de mois par groupe
- **Mode édition planche** : redirection vers `/companions?bedId={id}&bedName={name}&returnTo=/garden/{gardenId}`, bandeau info bleu, boutons « Retour à la planche » et « Annuler », nettoyage de la sélection à l'entrée et à la sortie
- **NSwag** : client TypeScript régénéré avec les endpoints Garden et Bed
- Nouvelles clés de traduction dans `fr.json` pour tout le module jardins
- Classes CSS réutilisables : `.list-panel`, `.list-panel-item`, `.section-divider-title`

### Infrastructure

- Aucun changement d'infrastructure dans cette branche

### Points d'attention

- Les US-005 à US-007 (ajout/modification/suppression de planches depuis l'UI) restent à implémenter — l'API backend est prête mais le frontend ne propose pas encore de formulaire dédié
- Le `PlantBadge` est désormais le composant standard pour afficher un nom de plante cliquable — à réutiliser dans les futurs écrans
- Le mode édition de planche repose sur des query params (`bedId`, `bedName`, `returnTo`) pour le contexte de navigation
