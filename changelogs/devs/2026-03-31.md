### Backend

- Entites `Garden` et `Bed` avec champs `Name`, `UserId`, relations one-to-many
- DTOs : `GardenDto`, `CreateGardenRequest`, `UpdateGardenRequest`, `BedDto`, `CreateBedRequest`, `UpdateBedRequest`
- `IGardenService` / `GardenService` : CRUD jardins avec filtrage par `UserId`
- `IBedService` / `BedService` : CRUD planches rattachees a un jardin
- `GardensController` (`api/gardens`) et `BedsController` (`api/gardens/{gardenId}/beds`) avec routes RESTful en kebab-case
- Migration EF Core pour les tables `gardens` et `beds` (snake_case)

### Frontend

- **GardenService** et **GardenStore** : gestion d'etat par signaux Angular, chargement des jardins et planches avec plantes associees
- **GardenListComponent** : liste des jardins en panel avec items divises, tri alphabetique
- **GardenViewComponent** : vue detail d'un jardin avec planches en collapsibles, boutons modifier/supprimer cote a cote, breadcrumb de retour
- **Bed panels** : affichage des plantes en lecture seule via `PlantAssociationPanel`, section d'actions avec bouton "Modifier", calendrier par planche
- **PlantBadge** (`PlantBadgeComponent`) : nouveau composant reutilisable affichant le nom d'une plante en badge colore. Utilise dans les en-tetes de planches, les cartes de guildes et l'assistant de guildes. Supporte les inputs `plantId` + `plantName`, clic pour ouvrir le detail
- **Calendrier global jardin** : integration des plantes de jardins dans le calendrier principal avec filtre source (toutes / mes plantes / jardins) et regroupement par jardin avec en-tetes de mois par groupe
- **Mode edition planche** : redirection vers `/companions?bedId={id}&bedName={name}&returnTo=/garden/{gardenId}`, bandeau info bleu, boutons "Retour a la planche" et "Annuler", nettoyage de la selection a l'entree et a la sortie
- **NSwag** : client TypeScript regenere avec les endpoints Garden et Bed
- Nouvelles cles de traduction dans `fr.json` et `en.json` pour tout le module jardins
- Classes CSS reutilisables : `.list-panel`, `.list-panel-item`, `.section-divider-title`

### Infrastructure

- Aucun changement d'infrastructure dans cette branche

### Points d'attention

- Les US-005 a US-007 (ajout/modification/suppression de planches depuis l'UI) restent a implementer -- l'API backend est prete mais le frontend ne propose pas encore de formulaire dedie
- Le `PlantBadge` est desormais le composant standard pour afficher un nom de plante cliquable -- a reutiliser dans les futurs ecrans
- Le mode edition de planche repose sur des query params (`bedId`, `bedName`, `returnTo`) pour le contexte de navigation
